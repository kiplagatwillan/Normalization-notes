	Normalization in Database Management System

- normalization is important process that help in database design that help improve database's considtency,efficiency and accuracy.

- It is the process that organizes the attributes of database to elimante data redundancy.

- data redundancy increases  size od database by same data in many places.

-Normalization  generally involves splitting tables into multiple ones which must be linked each time  a query is made requiring data from split tables.

     WHY DO WE NEED NORMALIZATION?

- Pimary objective of database id to remove anomalies.

1. Insertion anomalies - occurs when it is not posible to insert data into a database because the required fields are missing or the data is incomplete. For example if a database requires that very record has a primary key, but no values is provided for a particular record, it cannot be inserted into a database.  

2. Deletion anomalies - occur when deleting a record in a database and results in the unintentional loss of data. For example if a database  contains and orders, deleting a customer record may delete all the records with that customer.

3. Updating anomalies  - occur when modifying data in database and can result in inconcistencies or errors. For example if database contains employees and their salaries, updating an employees's salary in one record but not in one all related record could lead to incorect calculations and reporting.
 

              FEATURES OF DATABASE NORMALIZATION
1. Elimination of data redundancy - Normalizion helps in reducing  or eliminating the redundancy, which can improve the efficiency and consistency  of database. 

2. Ensuring data consistency:  Ensure data in database is accurate and consitent. This help prevent contradictions that arises due to different versions.

3. Simplification of data management -  Does this by breaking down complex data structure into simpler tables, normalzation make it easier to manage the data, update it and retrieve it.

4. Avoiding anomalies - Ensure that each table contains only one type of data and relationships between tables are clearly defined, which helps avoid anomalies.
 
5. Standardization: By organizing data in tables and refining relationships between them, normalization helps in ensuring that data is stored in consistent and uniform manner.

NORMAL FORMS IN DBMS

1. first normal form (1NF)- A relation is first normal form if every attribute in relation is single-valued attribute. 
 
A relation is said to be first normal form if:
(a) All the attibues contain atomic(indivisible) values.
(b) Each collumn contains values of a single type.
(c) There are no repeating groups or arrays in any rows

Rules for First Normal Form (1NF) in DBMS

- Every collumn must have a unique name. This avoids confusion when rerieving, updating or adding data.

- The order of data does not matter - order which data is stored does not affect how tables works.

2. second normal form(2NF) - A relation that is in first normal form and every non primary key  attribute is fully funtionally dependent on primary key, the relation is in second normal form(2NF).

- For a relation to be in 2NF, it must meet the following requirements:
(a)  Meet 1NF requirements: 
     - all columns containns single indivisible value
     - no repeatinf groups of collumns
(b) Partial dependency occurs when a non-prime attribute (not part of the candidate key) depends only on a part of a composite primary key, rather than the entire key.

  - 2NF is more efficient and less prone to errors during updates, inserts, and deletes.

Partial dependencies: 

-If you have a composite key (a primary key made up of more than one attribute), and an attribute depends on only a subset of that composite key, rather than the entire key, that is considered a partial dependency.
